# 仕上げて出す

## 1. 自分で見直す

差分を読み、次を1つずつ確かめる。

- 日付を日本時間で区切っているか
- エラーを握りつぶしていないか（空の catch、理由の無いメッセージ）
- 入力の検査が API 側にあるか
- 秘密の値や API キーをコードに書いていないか
- マイグレーションが「追加だけ」になっているか
- 使っていないコードやデバッグ用の出力が残っていないか

## 2. 検査を通す

- `pnpm verify` を通す
- 画面を変えたなら `pnpm test:e2e` も通す

## 3. プルリクエストを出す

- 作業用の枝に commit して push する（main には直接入れない）
- プルリクエストの説明には、何ができるようになったかと、確かめたことを日本語で書く
- 画面を変えたならスクショを河津さんに送る

## 4. 本番に反映される流れ

河津さんがプルリクエストを main に取り込むと、GitHub Actions が次の順で動く。こちらからは何もしない。

1. 検査（`pnpm verify`）
2. 本番の D1 にマイグレーションを当てる
3. Worker を反映する

反映の自動化は、GitHub の変数 `DEPLOY_ENABLED` が `true` のときだけ動く。
